# Survey Publisher

This skill publishes an already-generated survey bundle.

It does **not** generate schema or HTML.
It consumes the output of `survey-creator-skill`.

## Primary job

Take a survey bundle and produce:

- `surveyUrl`
- `schemaUrl`
- `htmlStorageUrl`
- `publish-record.json`

The skill should also update `survey.manifest.json` with publish metadata.

## Read these first

Before publishing, read:

- `../../docs/SKILL_SUITE_EVOLUTION.md`
- `./references/manifest-contract.md`
- `./references/publish-contract.md`
- `./references/provider-model.md`
- `./references/path-conventions.md`

If the provider is `tencent`, also use:

- `./references/providers/tencent.md`

## Expected input

Preferred input:

```text
/absolute/path/to/bundle/survey.manifest.json
```

Also acceptable:

- bundle directory path
- explicit html/schema/manifest paths

If the user only gives a bundle directory, resolve `survey.manifest.json` from it.

## Expected bundle

The bundle should contain:

```text
survey.html
survey.schema.json
survey.payload.sample.json
survey.report.json
survey.manifest.json
```

If the current generator output uses survey-id-based filenames, read paths from `survey.manifest.json` instead of guessing names.

## Publishing model

Separate publishing into two roles:

1. `archive`
2. `publicWeb`

### `archive`

Responsible for stable artifact storage:

- schema
- optional html archive

### `publicWeb`

Responsible for respondent-facing browser access:

- html

The provider may implement both roles using different services.

Example:

- Tencent: `archive = COS`, `publicWeb = CloudBase Hosting`

## Provider model

The root publishing flow should stay provider-neutral.

Only the provider adapter should know provider-specific commands, object keys, and verification details.

Current supported provider:

- `tencent`

Future providers can be added without changing the external publish contract.

## Publish modes

### `public-web`

Default mode.

Uploads:

- schema -> archive
- html -> public web layer
- optional html archive -> archive

Returns:

- `surveyUrl`
- `schemaUrl`
- `htmlStorageUrl`

### `archive-only`

Uploads:

- schema -> archive
- optional html -> archive

Returns:

- `schemaUrl`
- `htmlStorageUrl`

No respondent-facing URL is promised in this mode.

## Required config

The skill should require:

- a provider name
- provider config
- a valid manifest

Do not silently invent buckets, prefixes, or environment IDs.

## Execution flow

1. locate and read manifest
2. verify referenced files exist
3. extract `surveyId`
4. resolve provider adapter
5. build publish plan
6. upload schema to archive
7. optionally upload html archive
8. publish html to public web layer when mode requires it
9. verify the respondent-facing URL returns HTML rather than file-download behavior
10. write `publish-record.json`
11. update manifest

## Verification requirements

Do not consider publish successful unless:

- manifest parses
- html exists
- schema exists
- `surveyId` exists
- archive upload succeeds
- public-web upload succeeds when mode requires it
- the final `surveyUrl` returns HTML
- the final `surveyUrl` is browser-openable

If the provider returns attachment-style headers or download behavior, treat publish as failed.

## Failure behavior

If archive succeeds but public-web publish fails:

- preserve archive artifacts
- write a partial publish record
- do not mark manifest as fully published

If verification fails after upload:

- report the failing URL
- report relevant response headers if available
- do not return a successful publish result

## Scripts

Use these scripts when possible:

- `./scripts/publish_survey.py`
- `./scripts/verify_public_survey_url.py`
- `./scripts/providers/tencent.py`

If they are incomplete, improve them instead of re-describing the entire workflow in every answer.

## Output format

Return:

1. one-line publish summary
2. the final `surveyUrl`, `schemaUrl`, and `htmlStorageUrl`
3. any partial-failure note if publish is incomplete

Do not return long provider setup explanations unless the user asks.
