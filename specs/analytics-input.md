# Analytics input contract

The `survey-analytics` skill consumes:

1. one survey schema
2. one answers dataset

## Supported schema input

- the repaired schema generated by `survey-creator`
- a schema-equivalent survey JSON that follows the same field contract

## Supported dataset input

The answers dataset may use either of these shapes.

### Shape A: raw submission payloads

Example:

```json
{
  "surveyId": "survey-310992845731864576",
  "submittedAt": 1748320800000,
  "extra": {
    "utm_source": "wechat"
  },
  "answers": []
}
```

### Shape B: wrapped storage records

Example:

```json
{
  "submissionId": "submission-310992845731864577",
  "surveyId": "survey-310992845731864576",
  "submittedAt": 1748320800000,
  "receivedAt": 1748320800123,
  "payload": {
    "surveyId": "survey-310992845731864576",
    "submittedAt": 1748320800000,
    "extra": {
      "utm_source": "wechat"
    },
    "answers": []
  },
  "extra": {
    "utm_source": "wechat"
  }
}
```

## Supported file containers

- JSON array of records
- JSONL file with one record per line

Each record may be either Shape A or Shape B.

## Normalization rule

Before analysis, normalize each record into one effective answer document:

- if the record has `payload`, use `record.payload`
- otherwise use the record itself as the answer document

The normalized answer document must contain:

```json
{
  "surveyId": "survey-310992845731864576",
  "submittedAt": 1748320800000,
  "extra": {},
  "answers": []
}
```

## Dataset validity rules

Recommended input rules:

- every normalized record must belong to the provided `surveyId`
- malformed records may be excluded, but the analysis should report how many were excluded and why
- if the dataset mixes multiple surveys, records for other surveys should be dropped and reported
- empty `answers` arrays are allowed but should be reported as low-signal responses when relevant

## Recommended optional fields

These fields are useful if the adopter wants richer segmentation:

- `submissionId`
- `receivedAt`
- `ownerId`
- `workspaceId`
- `channelId`
- `projectId`
- `payload.extra.*`

The analytics skill should treat these as optional metadata, not required fields.

## Analysis boundary

`survey-analytics` is responsible for:

- summarization
- segmentation
- distribution analysis
- recommendations
- basic dataset health reporting

It is not responsible for:

- collecting responses
- validating login permissions
- hosting dashboards
- storing data
- mutating the source dataset
